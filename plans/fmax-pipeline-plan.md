# Fmax 优化：旋转锥流水化（提案 v1，待评审）

> 目标（用户指令 ①）：优化控制平面 Fmax。现基线：tt Fmax ≈ 14.7 MHz（sky130 口径），
> 关键路径 = `pos_base_reg[2] → row_reg[40][19]` 68.11 ns，100% 在逻辑侧
> `rope_sincos`（Cody-Waite 归约 + Hermite 插值）+ rotate 乘加链的组合锥。

## 1. 路径决策：否决「角度缓存宏化」（原阶段 2），主选「锥流水化」

### 1.1 角度缓存推演（否决理由，如实记录）
- ang4096x64 = 4096 字 × 64b = 32 KB，仅容 **128 位置**（每位置 64 对 cos/sin bf16 = 256 B）；
- 滑动窗口 R=2052 位置：全量缓存需 **2052×256 B = 525 KB** ≈ 4.2 Mbit → 28nm 约
  **1.7-2.8 mm²**（按 1.5-2.5 Mbit/mm² 密度区间）——远超 28nm 控制平面逻辑面积
  （sky130 口径 1.0 mm² 的 1/10 量级；跨工艺比较仅作量级参考，28nm 逻辑只会更小）；
- 128 位置滑动缓存 → 每 decode 步失效 = 2052−128 = **1924** 次重算 → 每层
  1924×64 ≈ 123K 次 rope_sincos（远超 HBM 预算 26,317 cyc 的容纳能力），回到原墙；
- 结论：角度缓存作为**主降路径否决**；ang4096x64 宏保留备用（未来小窗/短序列场景）。

### 1.2 主路径：行生产锥 register-slice 流水化
- 把 kv_bfeed S_DONE 的 K 行生产组合锥（68.11 ns，全锥 ≈ **28-31 个顺序 op 级**：
  头部 3 级 + rope_sincos ≈ 18-21 级（nf 乘→f32_to_i32→i32_to_f32→n2pi 乘→双减→
  条件双加→u 乘→桶移索引→i32_to_f32→f 减→LUT→h 乘→t1/t2→h·t2→h·t3→t4→h·t4→res，
  Hermite 乘加对融合计数）+ rotate 3 级 + bf16 舍入 3-4 级，每 op ≈ 2.3 ns sky130
  口径）切成 **~10-12 级流水，每级 ~2-3 op**（含
  **rope_sincos 内部 op 级切分**：Cody-Waite 归约后、LUT 索引/取表后、Hermite 链
  每个乘加对之间——与函数边界切同样 0 ULP 安全，op 次序不变）；
- **数值不变**：每一级之间只插寄存器，各 op 的舍入次序与顺序不变 → co-sim 仍 **0 ULP**
  逐位一致（同一组软浮点函数、同一序列）；
- 行生产延迟 +~10-12 cyc：row_valid 脉冲握手**已验证延迟无关**（CP 直接等待脉冲、
  无计数），延迟在 HBM 绑定调度下完全隐藏（B-feed 25,104 ≤ 26,317 口径只吞吐相关）；
- 吞吐不变：每周期仍 1×64b khat 读 + 1 行产出；
- 预期：关键路径 ≈ 单级深度（~7 ns sky130 口径）→ sky130 Fmax ≈ 130-140 MHz 量级；
  **验收锚定 28nm 口径**：与计划 B 衔接——SMIC28 新基线的 pre-pipeline Fmax 为
  「前值」，流水化后 28nm Fmax 为「后值」（14.7 MHz 仅作 sky130 历史参考值）。
-
### 1.3 附带轻量复用（调度级，非缓存）
每 token 每层的 cos/sin（64 对）在 8 head 间**复用**：行生产按 token 分组调度时同一位置
的 angle 流水结果供 8 head 共享——不改数值、不加存储，仅调度顺序（实现期按需，非验收项）。

## 3. 验收

- 流水化后 co-sim 0 ULP（逐位不变）；DC Fmax 数字与关键路径报告（流水级深度 = 新路径）；
- 否决角度缓存的推演记录入文档；不新增存储宏。

## 4. 风险

| 风险 | 对策 |
|------|------|
| 流水级切分破坏软浮点 op 次序/舍入 | 允许在 rope_sincos **内部 op 级**切分（Cody-Waite 后、LUT 取表后、Hermite 每乘加对之间）；op 次序与舍入次序不变 → 0 ULP 安全 |
| 流水后关键路径转移到别处（如 b_slice 拷贝/宏地址逻辑） | DC 报告如实定位新关键路径，逐级再切 |
| DC 综合自动打拍（retiming）与手切冲突 | 手切寄存器加 `(* keep *)`；若 retiming 有效则比较两种结果 |
