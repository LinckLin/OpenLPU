## 3. decode 每 token 权重读（0.6B vs 8B 设计上限交叉验证）

| dtype | 每层 (B) | 28 层 (B) | lm_head (B) | **每 token 合计** | 8B 上限占比 |
|---|---|---|---|---|---|
| INT8 | 15,730,944 | 440,401,920 | 155,582,464 | **596,048,896 B = 0.596 GB** | 7.87% |
| BF16 | 31,461,888 | 880,803,840 | 311,164,928 | **1,192,097,792 B = 1.192 GB** | 7.87% |

> spec §4 的 8B 设计上限 = **7.57 GB/token（INT8，dense 6.95G + lm_head 622M，不含 embedding）**。
> 0.6B 的 0.596 GB = 8B 的 **7.87%**。embedding 仅首 token 读单行 1024 元素（2 KB），忽略；
> RMSNorm 每层 2304 B 计入（占比 0.011%）。

### 3.1 decode token/s 天花板（HBM 带宽 ÷ 每 token 字节）

| dtype | 峰值 1.2 TB/s | sustained 720 GB/s |
|---|---|---|
| INT8 | 2013 token/s | 1208 token/s |
| BF16 | 1007 token/s | 604 token/s |

## 5. prefill / decode 逐层瓶颈

### 5.1 prefill（seq=128，MODE PF，整块 GEMM）

| 量 | 值 |
|---|---|
| 每层 dense MAC | 2,013,265,920（128×每层参数） |
| 每层 attention MAC（QK^T+AV） | 67,108,864 |
| 每层总 MAC | 2,080,374,784 ≈ 2.08 G |
| 计算时间（INT8 峰值） | 63.5 µs |
| 权重读时间（读一次，峰值） | 13.1 µs |
| 权重复用因子 | M=128（每权重被 128 输出行复用） |
| **瓶颈结论** | **计算受限**（63.5 µs > 13.1 µs） |

> 与 spec §2.1 结论一致：prefill M≫1 权重复用，HBM 权重流量 = 计算流量/M，远低于 1.2 TB/s，
> 阵列利用率 ~94–99%。

### 5.2 decode（seq=1，MODE DC，16 lane GEMV）

| 量 | 值 |
|---|---|
| 每层权重读（INT8） | 15,730,944 B |
| 每层权重读时间（sustained） | 21.85 µs |
| 每层计算（INT8 峰值） | 0.48 µs |
| 读:算比（sustained 口径） | 45.5× |
| lm_head 权重读 / 计算 | 216.1 µs / 4.75 µs |
| 每 token 总时长（sustained） | 828 µs → 1208 token/s |
| 阵列利用率 | 3.66%（1200/32768） |
| **瓶颈结论** | **HBM 权重流受限**（每层读 21.85 µs ≫ 算 0.48 µs） |

> 与 spec §2.2 一致：DC 权重流需求 32.77 TB/s vs HBM 1.2 TB/s = **27.3× 短缺**（硬件常数，与模型无关），
> 阵列被迫降至 1.2 TMAC/s，利用率 3.66%。读:算比 45.5× 为 sustained（720 GB/s）口径，
> 27.3× 为峰值（1.2 TB/s）口径，二者同源。

## 6. 需评审项：decode KV 重读流量

> spec 04 §2.4 注「KV 流量每层 ≈ 8 KB（KV.APPEND 写 + KV.GATHER 读当前 token）」与 05 §5.2 步 5
> 「KV.GATHER 载入窗口 [0,pos]」不一致：decode 每 token 实际从 HBM 重读**整个** K/V 窗口，
> 而非仅当前 token。按 05 口径，长上下文下 KV 重读不可忽略：

| context | KV 重读/层 (K+V, BF16) | 28 层重读/token | vs 权重读 0.596 GB |
|---|---|---|---|
| 128 | 528,384 B | 0.015 GB | 2% |
| 512 | 2,101,248 B | 0.059 GB | 10% |
| 1024 | 4,198,400 B | 0.118 GB | 20% |
| 2048 | 8,392,704 B | 0.235 GB | 39% |
| 4096 | 16,781,312 B | 0.470 GB | 79% |
| 8192 | 33,558,528 B | 0.940 GB | 158% |

> 8K 时 KV 重读 = 0.94 GB/token，约为权重读的 158%。
> 若计入，decode token/s 天花板需下调；建议 P3 时序模型按 05 口径核算 KV 重读，并回填 04 §2.4 的 KV 注记。

## 7. 结论

- **prefill 每层 = 计算受限**（M=128 权重复用，阵列利用率高），与 spec §2.1/§2.5 一致。
- **decode 每层 = HBM 权重流受限**（27.3× 短缺，利用率 3.66%），与 spec §2.2/§2.5 一致，为硬件常数、与模型无关。
- decode INT8 sustained 天花板 ≈ **1208 token/s**（0.6B），8B 设计上限为 95 token/s；
  0.6B 每 token 权重读 0.596 GB = 8B 7.57 GB 的 7.9%。
- 需评审项：decode KV 重读（05 §5.2 全窗口 vs 04 §2.4「≈8 KB」）影响长上下文 token/s 口径，待 P3 精化。
