# QCore 自身瓶颈审计与优化方法学（R-Audit）

> 通读 docs/p1-roofline、p3-sim-report、p5-m4、p6-opt-report、p10-asic-report、plans/p6-p7-plan，
> 冻结口径 720/240 GB/s、256 B/cyc 写、32.77 TMAC/s、KV 114,688 B/token(0.6B)/147,456(8B)。
> 所有 token/s 为 0.6B INT8 口径（除注明），时钟 1 GHz=1 cyc/ns。

## 1. 冻结口径与两级天花板（锚点）

| 口径 | 短 ctx | @4K | @8K | 出处 |
|---|---|---|---|---|
| 读口径 roofline（HBM 读，KV 单副本） | 1208 | 675 | 469 | p3 §3.4 / spec §4 |
| 写口径 roofline（SRAM 写口，KV.LOAD） | — | 488 | 257 | p6 §3.3 / p3 §6.3 |
| P6 调度实测（双缓冲+PREFETCH） | — | 481 | 255 | p6 §3.3 |
| INT4 权重读口径 | 2417 | 938 | 582 | p5 §2.5 |
| 8B 设计上限（INT8 sustained） | 95 | 88 | 82 | spec §4 |

> 关键结论：decode 的**真实当前墙 = SRAM 写口（写口径）**，不是读口径。P6 已证
> 「SRAM 写 > HBM 读合计」（4K 65,536 > 45,151），权重流完全隐藏于 KV staging 写之下。

**B1 补充（8B 口径）**：权重流需求 32.77 TB/s 是硬件常数、与模型无关；0.6B 每 token 权重读

在 4K 写口径总周期 2.05M 中占 10.5%，且**不与 KV staging 重叠**（尾部串行，p6 §3.3 注）。

**B3 补充**：GATHER(×4 副本) 已被裁决废弃为 LOAD 单副本（4K 262.9→65.7 µs/层，4.00×，p3 §5.1）；
但即便单副本，SRAM 写仍 > KV HBM 读（65,536 vs 23,302 @4K），是「写 256 < 读 720」的固有 1/2.8 比例。

## 3. 优化杠杆打分排序（收益 1–5 × 成本 1–5，成本 5=最易/最低成本）

收益量化口径 = 写口径天花板 481/255 的 delta（第一性推导，冻结常数代入；KV 量化推导见 §3.1）。

| 排名 | 杠杆 | 攻击 | 预计收益（数字） | 收益 | 成本 | 优先级 |
|---|---|---|---|---|---|---|
| 1 | **KV INT8 量化** | B2+B3 同时 | 4K 481→**866**(+80%)；8K 255→**488**(+91%) | 5 | 4 | **5** |
| 2 | **Fmax 收敛（DC 级综合 + BF16 主通路重标定）** | B6 | 129→331 MHz = **2.57×** 线性；目标 1 GHz = 7.75×（960/675/469） | 5 | 3 | **5** |
| 3 | **KV 重读消减（streaming/分层/选择性 + paged KV）** | B2 | 上界 1208（4K +151%、8K +374%）；全窗口驻留需 16/32 MiB > 8 MiB SRAM，**不可行**，部分驻留折中 | 4 | 2 | 3 |
| 3 | **speculative / multi-token 解码** | B1（27.3× 根本墙） | 唯一直接攻击 batch=1 权重流；2-token 高接受率 ≈ **1.5–1.8×** | 5 | 1 | 3 |
| 3 | **PF Vector-Matrix 重叠** | B5 | prefill 118.9→63.5 µs/层 = **1.87×**（仅 TTFT，decode 无感） | 3 | 4 | 3 |
| 3 | **SRAM 写口 256→512 B/cyc** | B3 | 4K 481→675(+40%)；8K 255→469(+84%)；**不如 KV INT8 的 866/488**（不砍 KV 读） | 3 | 2 | 3 |
| 7 | **INT4 权重（W4A16）** | B1 | 短 ctx 1208→2417(2×)；但 3/20 精度失败，**受正确性阻**；4K/8K 被 KV 读主导收益折半 | 2 | 3 | 2 |
| 7 | **指令发射优化（multi-issue/压缩）** | B4 | 现余量仅 13%@短 ctx；KV INT4+INT4 权重落地后（总周期 <700K）**将成为新墙**，提前预留 | 2 | 3 | 2 |

### 3.1 关键推导（KV 量化对写口径天花板的作用，冻结常数代入）

KV 元素量化使 KV 窗口字节 114,688→57,344(INT8)/28,672(INT4) B/token，**同时**砍 KV HBM 重读与
KV staging SRAM 写两条路径（写量 = 读量 ÷ 2.8 的镜像）：

| 配置 | 每层绑定资源 | 每 token 总周期 | token/s |
|---|---|---|---|
| v0（BF16 KV，写口径） | SRAM 写 65,536 | 28×65,536+216,087 = 2,051,095 | 488 |
| **KV INT8** | HBM 读 33,500（权重 21,849+KV 11,651） | 28×33,500+216,087 = 1,154,087 | **866** |
| **KV INT4** | HBM 读 27,674 | 28×27,674+216,087 = 990,959 | **1009** |
| 8K v0 | SRAM 写 131,072 | 28×131,072+216,087 = 3,886,103 | 257 |
| **8K KV INT8** | SRAM 写 65,536 | 28×65,536+216,087 = 2,051,095 | **488** |
| **8K KV INT4** | HBM 读 33,500 | 28×33,500+216,087 = 1,154,087 | **866** |

> 洞察：KV INT8 一箭双雕——既消 B2 又消 B3，收益超过「SRAM 写口翻倍」（后者只去写墙、不砍 KV 读，
> 天花板仅回到读口径 675/469）。且 ISA 已预留 KV dtype 字段（05 §4 v0 固定 BF16 code 0，需改 dtype+
> per-group scale 元数据 + KV.LOAD/STORE_BLOCK 步长），成本低于写口扩容。

## 4. 设计方法学建议（可执行）

### 4.1 qsim 时序模型 = 唯一 oracle 的 co-design 闭环

已有资产：`qsim/timing.py`（P3 四引擎模型，与 roofline 锚点 <0.1% 对齐）→ `qsim/timing_p6.py`
（P6 新增可选模型，不改基线）。方法学固化：

```
spec 冻结常数 → roofline 解析天花板 → qsim timing 建模 + 消融 → RTL co-sim 对拍 → ASIC STA 兑现
      (720/240/256/32.77)        (p1 口径)          (p3/p6)          (p7, ≤1 ULP)      (p10)
```

- **任何优化先落 qsim 时序模型，出「周期分解 + 消融 + 天花板 delta」三表，再进 RTL**。P6 §4 的
  消融表（serial 3.32M ❌ → 重叠 2.07M → 双缓冲 2.08M → 重读消减上界 0.83M）是范式：每个配置
  一行、贡献逐项隔离、收益落到 token/s。
- 反例教训（避免重演）：P6「488 公式」的「KV staging ⟂ 权重流重叠」假设若未先在资源级模型验证，
  会直接在 RTL 踩坑（p6 §6.1 已列为需评审项）。先建模型 = 用 1 天建模换 RTL 1 周返工。

### 4.2 消融门槛（防「优化了已隐藏的桶」）

**门槛：每个优化项必须证明其攻击的资源是当前关键路径上的绑定资源，且给出 Δtoken/s。**
- 反例：decode 的 Vector 桶（513 cyc/层）与矩阵计算（608 cyc/层）占 <1%，任何「更快的 softmax/
  GEMM 阵列」在 decode 都是无效投入（p3 §3.1 依赖 stall 26,554 cyc 才是空闲主体）。
- 反例：PF 双缓冲对 prefill 无收益（prefill 已计算受限，p6 §3.4 明示「重叠无作用」）——调度优化
  只作用于 decode 的 HBM/SRAM-bound 路径。
- **消融证据不足的优化不入 RTL、不写 spec**；消融表进交付物（对照 p6 §4）。

### 4.3 攻击关键路径、按优先级顺序

按 §3 排序执行：① KV INT8（最高收益/成本比，一箭双雕）；② Fmax 收敛（必做，是「兑现 1 GHz」的
前置，非可选）；③ KV 重读消减/speculative/SRAM 写口/PF 重叠 同列，按 SRAM 预算与 draft 模型成本
择优；④ INT4 权重（先解决 3/20 精度，再谈带宽）；⑤ 指令发射（为量化后新墙预留 multi-issue 余地）。

### 4.4 冻结常数共享 + 天花板口径纪律

- 冻结常数（720/240、256、32.77）是跨文档唯一 oracle，任何报告引用必须对齐（p1/p3/p6 已示范
  「同源偏差 <0.1%」）；新增优化推导必须注明代入公式 + 值与出处，禁止「拍脑袋 token/s」。
- 口径纪律：区分**读口径 / 写口径 / 实际调度**三层天花板（§1 表），报告 token/s 必须标明口径；
  当前真实墙是写口径，用读口径报数会高估 40%（675 vs 488 @4K）。

### 4.5 量化收益的验收闭环

优化做完不只看周期模型：INT8 量化验收 = 交叉一致率 ≥8/10（p6 已示范 10/10）；INT4 未达 3/20
即如实记录、不虚报（p5 §4.2-5）。每个带宽优化配精度消融，防止「带宽上去了、token 全错」。

## 5. 结论

1. decode 有**三层墙**：根本墙 = 权重流 27.3× 短缺（B1，硬件常数）；第二墙 = KV 全窗口重读
   （B2，8K 达权重读 158%）；当前绑定墙 = SRAM 写口（B3，写口径 488/257）。
2. 最高杠杆 = **KV INT8 量化**（+80%/+91%，同时拆 B2+B3）与 **Fmax 收敛**（2.57×，必做前置）；
   speculative 是唯一能攻击 B1 根本墙的方向（batch=1 约束下）。
3. 方法学 = 以 qsim 时序模型为 oracle 的 co-design 闭环 + 「先建模再动工」+「消融证据门槛」+
   「口径纪律」；反例（PF 双缓冲、decode Vector 优化）已在 P6 消融中实证「优化已隐藏桶无效」。
